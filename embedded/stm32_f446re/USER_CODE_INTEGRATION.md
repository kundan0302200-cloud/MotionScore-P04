# MotionScore Edge — NUCLEO-F446RE + LM35

## What this first hardware milestone does

This milestone measures real ambient temperature using an LM35, samples its analog output using ADC1 on the STM32, and sends timestamped samples over USART2 through the board's ST-LINK virtual COM port. The Python dashboard can capture samples, graph temperature, compare the latest measurement with a manually selected reference temperature, and export captured telemetry to CSV.

Important scope: this is sensor telemetry, not closed-loop temperature control. No heater/fan actuator or driver is available in the current hardware list. The simulation-trained Random Forest model is not used in STM32 Live Telemetry mode because it has not been trained or validated on this LM35 data.

## Hardware and wiring

| LM35 connection | NUCLEO-F446RE connection |
|---|---|
| Sensor supply (+Vs) | Board +5V pin |
| Analog output (Vout) | Arduino A0 / PA0 / ADC1_IN0 |
| Ground (GND) | Any board GND pin |

The TI LM35 datasheet specifies a 4 V minimum supply and a nominal output scale of 10 mV/°C. Therefore, power the sensor from the board 5 V pin, not 3.3 V. Connect grounds together. PA0 is an ADC input; never configure it as an output.

**Physical connection requirement:** A USB cable alone does not electrically connect the LM35 to the board. You need three suitable jumper-wire connections (and preferably a breadboard) if the sensor leads and board headers do not mate securely. Do not force bare sensor legs into sockets or risk shorting adjacent pins.

For the common TI LM35 TO-92 package, when looking at the flat face with leads pointing down, the usual order is +Vs, Vout, GND from left to right. Check the drawing for the exact part/package in hand before connecting power; breakout boards and other packages can have different pin layouts.

## STM32CubeIDE / CubeMX setup

1. Create a new STM32 project and select board NUCLEO-F446RE, or MCU STM32F446RETx if selecting by MCU.
2. Use the default board clock configuration for the first build.
3. Set PA0 to ADC1_IN0 / Analog. Do not select GPIO output and do not enable pull-up/pull-down.
4. Enable ADC1 regular channel 0, rank 1, 12-bit resolution, right alignment, software trigger, single conversion. Disable scan and continuous-conversion modes. Use a generous sample time such as 84 ADC cycles for the slow-moving sensor signal.
5. Enable USART2 in Asynchronous mode: 115200 baud, 8 data bits, no parity, 1 stop bit, no hardware flow control. Confirm PA2 is USART2_TX and PA3 is USART2_RX (alternate function AF7).
6. Generate code. It should provide ADC handle hadc1 and UART handle huart2 in adc.h and usart.h.

## Add the firmware module

Copy these repository files into the generated project:
- embedded/stm32_f446re/Core/Inc/motionscore_edge.h → generated Core/Inc/
- embedded/stm32_f446re/Core/Src/motionscore_edge.c → generated Core/Src/

In the generated Core/Src/main.c:
- Add #include "motionscore_edge.h" within USER CODE BEGIN Includes.
- After MX_GPIO_Init(), MX_ADC1_Init(), and MX_USART2_UART_Init(), call MotionScoreEdge_Init() in USER CODE BEGIN 2.
- Inside the existing while(1) loop, call MotionScoreEdge_Loop() in the user-code section.

Do not add a second main() function. Keep the main.c, clock setup, and initializers generated by CubeMX. If your generated peripheral handles have different names, update the module to match those names.

## Firmware behavior

- Reads 16 ADC conversions and averages the raw 12-bit counts.
- Reports every 500 ms using HAL_GetTick() scheduling.
- Sends ASCII CSV frames over USART2 with a CRLF line ending.
- Does not parse commands from the PC and does not drive an actuator.

Example frame (illustrative only):

    MS1,500,310
    MS1,1000,311
    MS1,1500,310

Format: MS1,<time_ms>,<adc_raw>. MS1 is the protocol/version marker, time_ms is the MCU tick, and adc_raw is in the range 0–4095.

## Build, flash, and find the COM port

1. Build in STM32CubeIDE and fix any CubeMX naming differences first.
2. Connect the board by its ST-LINK USB connector and flash/run the firmware.
3. In Windows Device Manager, check Ports (COM & LPT) for the ST-LINK Virtual COM Port. The exact COM number varies by PC.
4. Close PuTTY, Tera Term, the IDE's serial terminal, or any other tool holding that COM port open.
5. From the Python project environment, run:

    python -m pip install -r requirements.txt
    python -m streamlit run app.py

6. In the dashboard sidebar select STM32 Live Telemetry, enter the COM port (for example COM5), set baud rate to 115200, select an ADC reference estimate, and press Capture telemetry.
7. Download the captured CSV to preserve the run. Check sample count, temperature stability and sensible values before using the data for analysis.

## Temperature conversion

Assuming a 12-bit ADC and 3.3 V reference:

    voltage_mV = adc_raw × Vref_mV / 4095
    temperature_C = voltage_mV / 10

At approximately 25 °C, the LM35 output is about 250 mV. With a 3.3 V ADC reference this is approximately 310 counts. These are idealized examples: sensor tolerance, actual VDDA/reference, ADC characteristics, noise and wiring all affect readings. The dashboard exposes the reference voltage for calibration; it does not automatically measure VDDA. For accuracy, calibrate against a trusted thermometer and measured/calibrated ADC reference.

Basic configuration is intended for ordinary non-negative ambient-temperature monitoring. Negative temperatures would produce a negative LM35 output and are not measured correctly by this unmodified single-supply ADC interface.

## Dashboard live mode

The sidebar switches between Simulation Lab and STM32 Live Telemetry. Hardware mode:
- opens the selected serial port only when Capture telemetry is clicked;
- parses valid MS1 frames and ignores unrelated/malformed lines;
- converts ADC counts to an estimated temperature;
- reports the latest temperature, target-minus-measured deviation, sensor voltage and sample count;
- plots captured temperature against time and the selected reference temperature;
- allows CSV download.

The chosen target is only a visual reference. No fan or heater control occurs. The deviation warning is a threshold on the latest measurement, not a learned persistent-bias classifier. The model trained on simulated system features is not loaded in hardware mode.

## Troubleshooting

- No COM port: check the ST-LINK USB connector, driver, Device Manager and board revision.
- COM port busy: close serial terminal programs before clicking Capture telemetry.
- No valid data: verify firmware flashed/running and that the port settings are 115200 8-N-1.
- Temperature is implausible: re-check sensor pin order, common ground, 5 V supply, PA0/Vout connection, and ADC reference setting.
- Build errors mentioning hadc1 or huart2: check that ADC1/USART2 were generated in CubeMX and that your names match the module.
- ADC reads always zero or full scale: check sensor wiring and ensure PA0 is configured for ADC analog input.
